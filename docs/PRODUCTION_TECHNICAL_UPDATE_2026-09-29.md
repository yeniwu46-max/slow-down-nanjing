# 《宁可慢一点》生产演示版技术更新

> 更新日期：2026-09-29
> 适用范围：数媒竞赛版主站与线下答辩演示包
> 代码基线：`7971f0f` 及其之前的智能规划、实验与生产界面提交

## 1. 发布结论

本轮更新将项目从“多功能文旅产品原型”收敛为“可解释的南京文化慢游路线规划系统”。比赛主流程聚焦三个一级入口：

1. 智能路线规划。
2. 经典路线。
3. 项目原理。

主流程不再依赖智能体、情绪分析、手势、游戏、日记、账号、徽章或数字藏品等模块。这些历史代码仍被保留，但已解除入口与必要运行依赖，便于赛后研究与回溯。

生产界面同时删除了开发实现、评分口径和过度数据元信息等非必要解释文案，保留功能标签、可访问性语义、异常状态、路线理由、文化叙事与来源。

## 2. 智能规划链路

### 2.1 自然语言理解

- 使用 `Xenova/bge-small-zh-v1.5` 量化模型，由 Transformers.js Web Worker 在浏览器本地推理。
- 23 个 POI 在构建阶段生成 512 维 L2 归一化向量，查询时计算余弦相似度。
- BGE 负责文化语义与 POI 相关度；“少走路”“雨天室内”“无障碍”等确定性要求由规则转换为结构化约束。
- 模型缺失、Worker 失败或 WASM 不可用时，自动切换到本地关键词与标签匹配。
- 语义分只参与软偏好评分，不覆盖时间窗、闭馆、预算与用户确认地点等硬约束。

### 2.2 文化知识图谱

项目使用离线 JSON-LD 图谱组织南京文化信息，当前包含：

- 23 个地点实体、12 个受控文化主题、7 个历史时期。
- 19 个人物、事件或文化遗产实体。
- 110 条带来源、核验日期、证据等级和状态的文化关系。
- 14 项来源记录，优先使用政府、博物馆、公共文化机构与 UNESCO 资料。

规划器按用户确认的候选地点计算文化主题覆盖率，再根据实际游览顺序生成可追溯叙事链。找不到已核验连接时，系统只展示独立站点故事，不生成虚构过渡。

### 2.3 路网、时间窗与动态重算

- 运行时读取 Valhalla/OpenStreetMap 生成的 23 × 23 步行路网矩阵，共 529 个地点对。
- 闭馆、时间预算、建议停留、等待开馆和临时关闭均进入可行性求解。
- 智能路线综合效率、文化、语义、天气、体力、景观、拥挤和夜间适宜性。
- 结果页同时展示基准路线、智能路线和小规模精确最优验证路线。
- 天气、剩余时间、地点关闭、用户取消、体力与偏好变化可触发本地重算，无需重复运行 BGE。

OR-Tools 和 Valhalla 容器保留为可选建模与验证服务；比赛主站在这些服务未启动时仍可独立完成规划。

## 3. 算法实验与证据

项目建立了 12 个 POI 模板 × 5 组条件的 60 场景固定工程基准，包含 56 个可行场景和 4 个故意构造的不可行场景。

四组实验配置为 Full、No-BGE、No-KG 和 No-Weather，共生成 240 组功能结果；性能测试在 30 次预热后完成 1,200 次动态重算。当前固定环境结果：

| 指标 | 结果 |
|---|---:|
| 可行路线生成率 | 100% （56/56） |
| 不可行场景正确拒绝率 | 100% （4/4） |
| 超预算、闭馆与临时关闭硬约束违规率 | 0% |
| 动态重算 P95 | 8.11 ms |
| 超过 500 ms 比例 | 0% |
| BGE 暖推理 P95 | 4.72 ms |

所有汇总数字均由原始 CSV/JSON 生成，不在报告中手工填写。实验如实保留零提升与负结果，不以减少地点换来的距离下降宣称算法改进。完整方法见 [路线规划算法对照实验](./ROUTE_PLANNING_EXPERIMENTS.md)。

## 4. 生产界面与弱网策略

- 规划入口只采集起点、2–5 个候选地点、剩余时间、步行能力和路线偏好。
- 结果聚焦地图、总距离、步行时间、游览时间、预计完成时间、路线顺序、推荐理由与量化差异。
- 天气请求失败时使用缓存或备用数据，定位被拒绝时使用南京默认起点。
- BGE 模型、POI 向量、文化图谱和步行矩阵均可放入离线比赛包。
- 地图提供多样式候选与加载异常处理，规划器不依赖可选容器服务。

## 5. 依赖安全与 MapLibre 6 迁移

### 5.1 安全审计

升级前，生产依赖审计报告 2 个严重、3 个高危和 2 个中危问题；将开发依赖一并纳入后，全量审计为 3 个严重、6 个高危和 4 个中危问题。

本轮升级包括：

| 依赖 | 原版本 | 安全版本 |
|---|---:|---:|
| Next.js | 16.2.9 | 16.3.6 |
| MapLibre GL JS | 5.24.0 | 6.11.2 |
| Vitest | 3.2.4 | 4.1.11 |
| Tailwind CSS / PostCSS 插件 | 4.x / 4.3.1 | 4.3.3 |
| React Three Drei | 10.7.7 | 10.7.9 |

同时更新 Sharp、NanoID、fflate、Browserslist、brace-expansion 和 baseline-browser-mapping 等传递依赖。修复后，全量与 `--omit=dev` 两种 `npm audit` 口径均为 0 个漏洞。

### 5.2 MapLibre 6 工作线程

MapLibre GL JS 6 改为 ESM-only，不再提供默认导出。代码已迁移为命名空间导入。

Next.js 在 Webpack 与 Turbopack 下均不会自动把 worker 及其 `maplibre-gl-shared.mjs` 依赖成对发布。项目因此在 `predev` 和 `prebuild` 中执行 `scripts/copy-maplibre-worker.mjs`，将两个文件从当前安装版本复制到 `public/maplibre/`，再调用：

```ts
maplibregl.setWorkerUrl("/maplibre/maplibre-gl-worker.mjs");
```

这保证 worker 版本与主包一致、保持同源，并允许离线部署。实现依据 [MapLibre 官方 ESM/Next.js 集成说明](https://maplibre.org/maplibre-gl-js/docs/#esm)。

## 6. 运行与部署

### 6.1 基本环境

- Node.js `>=20.9.0`。
- npm 10 或更高版本。
- 现代桌面或移动浏览器；MapLibre GL JS 6 需要 WebGL2。

### 6.2 生产构建

```powershell
npm ci
npm run build
npm start
```

`npm run build` 会先生成 MapLibre worker 静态资产，再执行 `next build --webpack`。

GitHub 不保存 BGE 模型、WASM、OSM PBF 和预构建路网。完整离线演示包需另行包含：

- `public/models/bge-small-zh-v1.5/`
- `public/wasm/`
- `integrations/data/shared/nanjing.osm.pbf`
- Valhalla 预构建路网
- GraphHopper 验证缓存（如需展示技术验证工具）

## 8. 数据与表述边界

- 步行路网是带时间戳的 Valhalla/OpenStreetMap 离线快照，不是实时路况。
- 开放时间、拥挤、景观、遮蔽和体力成本中的部分字段为项目参考数据，界面不将其宣称为实时城市数据。
- BGE 输出是候选地点间的相对语义匹配分，不是概率。
- 文化事实与项目原创表达在数据上分离；页面未标注更新时间时保留 `null`，不推测日期。
- 60 个场景是固定工程基准，不是针对目标人群的随机抽样研究。

## 9. 后续维护规则

1. 更新 POI 文化数据后，必须重新生成图谱并检查 BGE 向量版本。
2. 更新 MapLibre 时，必须通过 `predev`/`prebuild` 重新生成 worker 与 shared 文件，不单独复制其中一个。
3. 更新路网快照时，必须记录引擎版本、生成时间、坐标哈希和数据署名。
4. 发布前必须同时执行全量与生产依赖审计，并在真实浏览器检查 MapLibre worker。
5. 新的性能或算法结论必须来自可复现原始数据，不手工修改报告数字。
