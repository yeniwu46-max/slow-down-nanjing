# 路线规划算法对照实验与复现说明

> 更新日期：2026-09-28  
> 适用范围：比赛版 `/planner`、现有 23 个南京 POI  
> 机器生成的统计结果以 [`experiments/route-planning/summary.json`](../experiments/route-planning/summary.json) 为准。

## 1. 建设目标

本阶段把原来主要用于界面展示的“基准路线、智能路线、最优验证路线”升级为可重复运行、可审计、可用于答辩举证的工程实验。

实验需要同时回答四个问题：

1. 规划器能否在预算、开放时间和临时关闭等硬约束下稳定生成可行路线？
2. 智能路线相对固定顺序基准路线改善了什么，是否以减少地点为代价？
3. BGE、文化知识图谱和天气规则各自贡献了什么？
4. 动态重算能否满足 500ms 的比赛现场要求？

实验报告中的数字不手工填写。场景、语义结果、路线结果、汇总统计、图表和 PDF 均由同一条脚本流水线生成。

## 2. 固定实验集

实验集由 12 个 POI 模板和 5 个条件配置做笛卡尔组合，共 60 个场景。场景顺序、ID、候选地点、出发时间和预算均提交到仓库，运行时不随机修改。

### 2.1 主题模板

- 六朝古都、民国建筑、秦淮城南、明城墙
- 钟山风景、博物馆城市史、佛教文化、湖泊慢游
- 低体力街区、无障碍友好、城市夜游、综合跨区

### 2.2 条件配置

| 配置 | 主要条件 | 验证重点 |
|---|---|---|
| 雨天低体力短时 | 45–60 分钟、雨天、低体力 | 室内和遮蔽适配 |
| 早晨等候开馆 | 08:00 出发、固定起点 | 等待时间与开放时间窗 |
| 下午临近闭馆 | 16:10 出发、临时关闭点 | 闭馆约束和正确拒绝 |
| 日间文化偏好 | 180 分钟、自然语言需求 | BGE 与文化图谱 |
| 周末傍晚夜游 | 17:30、避开拥挤、夜游 | 夜间开放和体验评分 |

精确求解器判定其中 56 个场景可行。另有 4 个故意构造的不可行场景，用于验证系统不会在候选地点全部临时关闭时伪造路线。

## 3. 对照路线与独立复核

| 路线 | 方法 | 用途 |
|---|---|---|
| 基准路线 | 用户勾选顺序 + 时间窗截断 | 无智能排序的朴素对照 |
| 智能路线 | 多目标评分 + 离线 Valhalla 步行矩阵 | 正式比赛方案 |
| 最优验证路线 | ≤5 POI 全子集、全排列精确枚举 | 校验完成地点数和总用时差距 |

智能路线的 `feasible` 字段不作为实验结论。实验器会根据每站到达、离开时刻，独立复核预算、闭馆时刻和临时关闭地点。距离与总时间改进率只在基准路线和智能路线完成地点数相同时计算，防止把“少去地点得到的短路线”描述为算法改进。

## 4. 单因素消融设计

`RecommendationOptions` 新增三个独立开关：

```ts
interface PlannerFeatureFlags {
  semanticPreference: boolean;
  cultureGraphScoring: boolean;
  weatherAdaptation: boolean;
}
```

实验包含 Full、No-BGE、No-KG 和 No-Weather 四组配置。开关只移除相应模块的规划加分，不删除输入数据，也不关闭后验指标计算。因此 No-BGE 仍使用 Full 组的真实 BGE 固定结果评估语义匹配度，No-KG 仍计算文化覆盖率，No-Weather 仍计算室内占比、遮蔽和景观评分。

## 5. BGE 固定结果

实验使用本地 `Xenova/bge-small-zh-v1.5` q8 模型，revision 固定为：

```text
75c43b069aac4d136ba6bc1122f995fedcfd2781
```

12 条自然语言需求由本地模型实际推理，使用中文检索指令、CLS pooling 和 L2 normalization。输出包含每个 POI 的余弦相似度、相对匹配分、文化实体、解释依据和推理耗时，保存于 `semantic-fixtures.json`。

路线动态重算复用固定语义结果，不重复加载模型。模型冷启动和暖推理耗时单独统计，不混入路线重算性能。

## 6. 统计口径

对主要指标报告均值、中位数、样本标准差、Q1、Q3、IQR、P95、最小值和最大值。配对比较同时报告胜、平、负次数，并使用固定种子 `20260928` 进行 10,000 次 bootstrap，生成均值差 95% 区间。

该实验集是固定工程基准，并非随机抽取的游客样本，因此不使用显著性 p 值，也不把 bootstrap 区间解释为人群统计推断。

## 7. 当前基准结果

以下是 2026-09-28 完整流水线的结果快照。可机读原始值和精度以 `summary.json` 为准。

| 指标 | 结果 |
|---|---:|
| 可行路线生成率 | 100%（56/56） |
| 不可行场景正确拒绝率 | 100%（4/4） |
| 超预算、闭馆、关闭地点违规率 | 0% |
| 平均文化覆盖率 | 72.39% |
| 智能路线相对基准平均多完成地点 | 0.80 个 |
| 智能路线相对基准文化覆盖提升 | 15.96 个百分点 |
| 与精确解完成地点数差 | 0 |
| 等覆盖下相对精确解平均总时间差 | 5.91 分钟 |
| 与精确解完全一致场景 | 31 个 |

消融实验的平均配对差：

| 消融项 | Full 相对关闭组的变化 |
|---|---:|
| BGE | 语义匹配分 +1.83 |
| 文化知识图谱 | 文化覆盖率 +2.02 个百分点 |
| 天气规则（雨天） | 室内停留占比 +8.33 个百分点 |
| 天气规则（晴天） | 景观评分 +1.17 |
| 天气规则（雨天道路遮蔽） | 0，作为零结果保留 |

距离和总时间在等地点数场景中的 bootstrap 区间跨越 0，因此报告明确写作“没有稳定优势”，不筛除或隐藏负结果。

## 8. 性能测试

性能测试先执行 30 次不计入统计的预热，再对 Full 配置下每个场景重复运行 20 次，共 1,200 个样本。

- 平均重算耗时：2.97ms；
- P50：2.53ms；
- P95：8.11ms；
- 超过 500ms 的比例：0%；
- BGE 冷启动：139.69ms；
- BGE 暖推理 P95：4.72ms。

发布门槛是路线重算 P95 小于 500ms，且超过 500ms 的比例不高于 1%。不同机器的绝对耗时会变化，因此每次完整运行会记录操作系统、CPU、Node.js 版本、Git SHA、路网矩阵哈希、图谱版本和 BGE revision。

## 9. 文件结构

```text
experiments/route-planning/
├── scenarios.json            # 60 个固定场景
├── semantic-fixtures.json    # 12 条真实本地 BGE 结果
├── results.csv               # 60 × 4 功能实验长表
├── performance.csv           # 1,200 个性能样本
├── summary.json              # 统计汇总、区间与环境信息
├── report.md                 # 中文报告源文件
├── report.html               # 自包含排版版本
├── report.pdf                # 9 页 A4 参赛版报告
└── charts/*.svg              # 答辩可用矢量图
```

核心代码：

| 文件 | 职责 |
|---|---|
| `src/lib/map/recommend.ts` | 消融开关、候选评分和路线规划 |
| `src/lib/experiments/route-experiment.ts` | 实验配置、描述统计和 bootstrap |
| `tools/generate-route-experiment-scenarios.ts` | 固定场景生成 |
| `tools/generate-semantic-experiment-fixtures.ts` | 本地 BGE 固定结果生成 |
| `tools/run-route-experiment.ts` | 功能、消融、独立复核与性能实验 |
| `tools/render-route-experiment-report.ts` | SVG、Markdown、HTML 和 PDF 生成 |
| `tools/verify-route-experiment.ts` | 产物、统计口径和 PDF 完整性校验 |

## 10. 复现与维护

完整重建：

```bash
npm run experiment
```

也可依次运行 `experiment:scenarios`、`experiment:semantic`、`experiment:routes`、`experiment:report` 和 `experiment:verify`。完成后继续执行：

```bash
npm test
npm run lint
npm run build
```

POI、开放时间、路网矩阵、知识图谱或语义向量变化后，必须重新运行完整实验，不能只修改报告中的数字。

## 11. 数据边界

- 场馆开放时间、拥挤、景观、遮蔽和舒适度中的部分字段是项目样本，不是实时城市数据。
- 路网矩阵是带生成时间与哈希的离线 OpenStreetMap/Valhalla 快照。
- 当前实验只覆盖现有 23 个 POI 和不超过 5 个候选地点。
- 结果证明的是该固定工程基准下的行为，不代表所有南京游客和所有实时出行情形。

架构决策及备选方案见 [`ADR-001`](./decisions/ADR-001-REPRODUCIBLE-ROUTE-BENCHMARK.md)。
