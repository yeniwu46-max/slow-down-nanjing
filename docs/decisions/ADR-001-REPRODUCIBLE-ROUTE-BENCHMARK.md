# ADR-001：使用固定场景、精确枚举与单因素消融验证路线规划

## 状态

Accepted

## 日期

2026-09-28

## 背景

比赛版已经可以展示基准路线、智能路线和最优验证路线，但单个演示场景无法证明算法在不同天气、时间窗和文化偏好下的稳定性。若直接人工挑选案例或手填报告数字，结果难以复查，也容易只保留正向案例。

现阶段用户最多确认 5 个 POI，因此可以精确枚举全部子集与顺序，得到可靠的可行性与最优性验证基准。同时，BGE、文化图谱与天气评分存在共同输入，必须避免关闭某个模块时同时改变其他硬约束。

## 决策

1. 固定提交 12 个 POI 模板与 5 个条件配置组成的 60 个场景，不在运行时随机生成。
2. 使用 ≤5 POI 精确枚举结果作为可行性和最优性验证基准。
3. 使用三个独立 feature flag 分别关闭 BGE、文化图谱评分和天气适配，其他输入与约束保持不变。
4. 关闭模块时仍运行统一后验评估器，保证语义、文化与天气指标可比较。
5. 所有报告数字从 CSV/JSON 原始结果生成，不允许手工填写统计结果。
6. 使用描述统计、胜平负和固定种子的配对 bootstrap；不使用显著性 p 值。
7. 模型冷启动、暖推理和路线动态重算分别计时。

## 备选方案

### 随机生成大量场景

- 优点：场景数量容易扩大。
- 缺点：每次运行输入变化，难以复现；随机分布也未必代表真实游客。
- 未采用原因：当前目标是竞赛工程验收，稳定、可解释的固定基准更重要。

### 只展示若干典型案例

- 优点：报告简短，容易讲解。
- 缺点：存在选择性展示风险，无法计算违规率、P95 和消融分布。
- 未采用原因：不能充分支撑“智能性”和“稳定性”的技术主张。

### 用 OR-Tools 结果作为唯一真值

- 优点：可扩展到更大规模问题。
- 缺点：增加现场服务依赖；≤5 POI 时精确枚举更透明，也更容易审计。
- 未采用原因：当前规模下本地精确枚举能给出确定结果，OR-Tools 保留为后续扩展验证服务。

### 对每项改进报告显著性 p 值

- 优点：形式上接近学术实验。
- 缺点：60 个场景是人为固定的工程测试集，不是从目标人群随机抽样；p 值会制造不成立的推断语境。
- 未采用原因：使用配对差、效应大小和 bootstrap 区间更符合本实验的证据边界。

## 影响

正面影响包括稳定复现、独立违规复核、正负结果统一保留，以及报告、图表与原始数据可追溯。代价是固定场景不能代表全部游客，精确枚举只适用于当前 ≤5 POI 范围，且性能数字与运行机器相关。

## 后续约束

- 扩充 POI 或候选点上限时，需要新增 ADR，说明精确枚举向启发式或 OR-Tools 求解迁移的策略。
- 修改指标定义时必须同步更新验证脚本和技术文档，不能只修改报告文案。
- 不得将离线路网快照、项目样本开放时间或拥挤评分描述为实时城市数据。
